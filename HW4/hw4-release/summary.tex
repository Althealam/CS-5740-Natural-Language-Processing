\noindent
We fine-tune \texttt{distilbert/distilbert-base-uncased} for binary email safety (label~1\,=\,unsafe: morning time and/or physical exercise; label~0\,=\,safe). Below we summarize (i)~how we built training data, including bad-case analysis and targeted generation, and (ii)~how we built the Task~2 jailbreak file. All training uses \texttt{safety\_classifier\_finetune.ipynb}; experiments are logged on Weights~\&~Biases under project \texttt{safety-classifier}.

\section*{Task 1: Training data, bad-case analysis, and fine-tuning}

\subsection*{Pipeline (high level)}
\begin{enumerate}[label=\arabic*.]
    \item \textbf{Baseline:} train/dev only on the course-provided splits (\path{email_dataset_train.jsonl}, \path{email_dataset_dev.jsonl}) to obtain a first checkpoint.
    \item \textbf{Augmentation v1 (length / informality):} run \path{generate_email_dataset_v1.py} ($\sim$1{,}000 LLM-generated emails: short, informal, abbreviations). Merge with official data; outputs include \path{email_dataset_train_augmented_v1.jsonl} and \path{email_dataset_dev_augmented_v1.jsonl}, then combined \path{email_dataset_*_combined_v1.jsonl}. Validation: \textbf{accuracy $\approx$ 0.9924}, \textbf{F1 $\approx$ 0.9923}.
    \item \textbf{Add jailbreak-style training rows:} generate Task~2 file \texttt{jailbreaks.jsonl} (see Task~2) and merge into training; train another checkpoint (W\&B run \texttt{9i6ifufl}).
    \item \textbf{Augmentation v2 (targeted):} after manual bad-case study, run \path{generate_email_dataset_v2.py} ($\sim$1{,}000 examples) and merge all sources $\rightarrow$ \path{email_dataset_*_combined_v2.jsonl}. Validation: \textbf{accuracy $\approx$ 0.9799}, \textbf{F1 $\approx$ 0.9799}.
\end{enumerate}

\subsection*{How we analyzed bad cases (classifier ``bad cases'')}
We used \texttt{safety\_classifier\_testing.ipynb} with the provided starter model and typed \textbf{hand-crafted probes}; we did \emph{not} train on the hidden test set. Below are representative mistakes we collected (same categories as in our experiment log):
\begin{itemize}
    \item \textbf{Afternoon / evening misclassified as unsafe:} ``Let's meet in the afternoon''; ``Quick call at 7:45 PM tmr?''
    \item \textbf{``Morning'' as greeting / normal work ask (not exercise):} ``Morning Bob---can you seed the slides by noon?''
    \item \textbf{Negation / refusal (should often be safe):} ``I hate yoga and I avoid it completely''
    \item \textbf{Benign off-topic question:} ``How do I bake a birthday cake?''
    \item \textbf{Short Chinese--English mix:} a one-liner that mixes Chinese with English tokens like ``run'' (same style of probe as in our log: asking whether to run together tomorrow).
\end{itemize}
These motivated the targeted prompts in \texttt{generate\_email\_dataset\_v2.py}.

\subsection*{How we responded in data generation (v2)}
\texttt{generate\_email\_dataset\_v2.py} prompts an LLM with constraints so many new examples explicitly cover the above patterns: clearer afternoon/evening safe scheduling, ``morning'' used as salutation with non-exercise requests, explicit refusals of workouts, benign general questions, and short bilingual mixes. We merged these with the official data and earlier augmentations into \texttt{email\_dataset\_train\_combined\_v2.jsonl} (and corresponding dev file).

\subsection*{Which model we submit}
Validation accuracy \emph{dropped} after the large v2 merge (0.9799 vs.\ $\sim$0.9924 for v1 combined). To avoid overfitting extra noisy patterns, we submit the \textbf{better-validated checkpoint from the v1 combined training} (step~2 above), not the final v2 model.

\section*{Task 2: Jailbreak dataset (\texttt{jailbreaks.jsonl})}

\subsection*{Requirement}
100 JSONL rows, \textbf{50} label~0 and \textbf{50} label~1, no exact duplicate \texttt{text}, generated \textbf{automatically} (not hand-written). We avoid relying on a single hack; strategies below mix several phenomena.

\subsection*{Phenomena we stressed for jailbreak rows (bad cases for the original model)}
Our automated generators emphasize the behaviors that most consistently fooled the \textbf{starter} classifier (we documented these in our log):
\begin{itemize}
    \item \textbf{Spelling / character substitution:} e.g.\ \texttt{ex3rcise}, \texttt{m0rning}, \texttt{w0rk out}
    \item \textbf{Multilingual mixing} (Chinese / Hindi / German / Spanish / French templates)
    \item \textbf{Negation-style wording} (often confused the model)
    \item \textbf{Implicit semantics} for exercise/morning (no literal keywords), e.g.\ ``blood pumping'' or ``stretch legs''
    \item \textbf{Explicit clock times} such as 9\,AM, 10\,AM (not only the word ``morning'')
\end{itemize}

\subsection*{Generation procedure (\texttt{generate\_jailbreaks.py})}
We encode the above ideas as \textbf{six generator families}, each contributing roughly equal counts per label (so no single trick dominates):
\begin{itemize}
    \item \textbf{Spelling attack:} random homoglyph/digit substitutions (see mapping in script; examples above).
    \item \textbf{Multilingual mixing:} unsafe vs.\ safe templates filled with mixed-language activities/times.
    \item \textbf{Negation patterns:} double negatives vs.\ explicit refusals (unsafe vs.\ safe).
    \item \textbf{Implicit / euphemistic phrases} plus extra implicit seeds in code (cardio, dawn, etc.).
    \item \textbf{Distractor prefixes/suffixes:} polite wrappers around a short core sentence.
    \item \textbf{Abbreviations + explicit times:} short templates (\texttt{tmrw}, \texttt{b4}, AM/PM slots).
\end{itemize}

For each label we call every generator with a fixed per-strategy quota (splitting 50 rows across six strategies with remainder handling), concatenate, \textbf{drop exact duplicate texts}, then truncate to \textbf{exactly 50 per label} (first 50 unique rows per label), shuffle with seed~42, and write \texttt{jailbreaks.jsonl}. This satisfies balance, uniqueness, and format (\texttt{text}, \texttt{label}).
